Metadata, Clip Attributes, and Smart Bins

Part II of XVI
Category Practical
Sheet 010 / 095
Depends On 2.3
Read Time ~8 Min

Chapter 2.2 promised that smart bins would come back once you understood how to build the metadata they search against. This chapter delivers on that — metadata is the raw material, and a bit of disciplined tagging as footage comes in is what turns "I have 400 clips somewhere in this project" into "I have exactly the 12 clips I need, found in four seconds."

Two Kinds of Metadata: Captured and Added

Every clip arrives already carrying a layer of metadata your camera generated automatically — timecode, frame rate, resolution, codec, lens data on some systems, sometimes GPS or shooting date. Resolve reads and displays all of this without you doing anything, and it's genuinely useful: Chapter 2.6 leans on exactly this captured metadata when discussing how to recognize what you're working with at a glance. But captured metadata describes the file, not the content — it can't tell you which take was the good one, or which clips belong to a specific scene beyond what a folder name implies.

That's the gap added metadata fills: fields you or your team fill in deliberately, describing what's actually in the footage — a scene number, a shot description, keywords, a quality flag. This is manual work, and on a large shoot it's real work, often done by an assistant editor or logger rather than the editor themselves. But it's an investment that pays for itself the moment a director asks for "that shot where she looks out the window, sometime in the first week" and you can find it by searching rather than scrubbing through hours of footage by eye.

Captured metadata tells you what a file is. Added metadata tells you what's actually happening in it — and only the second kind makes a project searchable in any way that matters creatively.

Flags, Colors, and Ratings: Fast, Low-Effort Tagging

Not all added metadata needs to be a typed description. Resolve gives you lightweight tagging tools built for speed: clip flags (small colored markers you can apply and search on), clip color labels, and star ratings. These are worth using constantly during an initial footage review pass, precisely because they're fast — a single keystroke to flag a clip as a likely select while you're scrubbing through dailies is sustainable in a way that stopping to type a full description for every clip isn't. Save the more detailed typed metadata for the clips that actually make the cut, or for material where a short flag genuinely isn't enough information.

The Clip Attributes Dialog: Fixing What the Camera Got Wrong

Occasionally, metadata isn't just incomplete — it's wrong, or it needs manual correction for the project to behave properly. A common example: a clip's frame rate is misreported, or footage was shot at one frame rate but needs to conform to a different project frame rate, and Resolve's automatic interpretation isn't what you actually need. The Clip Attributes dialog is where you manually override this kind of metadata directly on a clip — correcting a frame rate, forcing a specific field order, or adjusting how Resolve interprets a file's properties. This isn't something you'll reach for often, but knowing it exists matters the first time footage behaves unexpectedly and the cause turns out to be a metadata mismatch rather than an actual problem with the file.

Turning Tags Into Smart Bins

With flags, ratings, and keyword metadata actually applied to your footage, smart bins from Chapter 2.2 stop being an abstract feature and become a genuinely fast way to work. A smart bin searching for "flag = select" surfaces your entire team's flagged footage across every day and every camera, automatically, the moment anyone applies that flag — no manual sorting required. A smart bin searching a keyword field for a character or location name does the same for content-based organization that a folder structure alone could never express cleanly, since a single clip might reasonably belong to more than one such category at once.

The practical habit worth building is this: decide, before a shoot or an ingest session starts, on a small, consistent vocabulary for flags and keywords — not an elaborate taxonomy, just enough shared language that everyone tagging footage uses the same terms. A "select" flag that means the same thing to every logger is worth far more than an elaborate metadata scheme nobody applies consistently.

Where This Leaves the Media Pool

Between Chapter 2.3's organized bin structure and this chapter's metadata layer, your Media Pool has gone from "a place footage technically lives" to "a genuinely searchable library of a production." That's real infrastructure, and it's worth treating as such — the ten minutes spent flagging a day's footage during ingest routinely saves far more than ten minutes of hunting later. Chapter 2.5 shifts focus from finding footage to actually being able to work with it smoothly, covering proxies and optimized media for projects where the source footage itself is heavier than your hardware can comfortably scrub in real time.

Key Concepts to Remember

  • Captured metadata describes the file automatically; added metadata describes the content, and only added metadata makes footage searchable by what's actually in it.
  • Flags, color labels, and ratings are fast enough to use during a first footage pass — save detailed typed descriptions for material that's already made the cut.
  • Clip Attributes lets you manually correct metadata the camera got wrong, like a misreported frame rate — rare to need, important when you do.
  • A small, consistently applied tagging vocabulary across a team beats an elaborate scheme nobody actually uses the same way.
