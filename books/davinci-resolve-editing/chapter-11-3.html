Chapter Eleven, Section Three

Presets for Common Destinations

Part XI of XVI
Category Practical
Sheet 068 / 095
Depends On 11.2
Read Time ~6 Min

Every decision Chapter 11.2 walked through — codec, container, bit depth, chroma subsampling, resolution, frame rate — has to be made correctly on every single render job a project produces, and a project routinely produces several, per Chapter 11.1's one-timeline-many-outputs reality. Rebuilding that full set of decisions by hand each time invites exactly the kind of small, easy-to-miss inconsistency that turns a technically fine render into a failed delivery. A preset is the tool that removes that risk.

What a Preset Actually Bundles

A render preset is simply every setting Chapter 11.2 covered, saved together as one named, reusable choice. Selecting a preset applies its codec, container, resolution, and other parameters all at once, rather than requiring each one to be set individually on every render job. This sounds almost too simple to be worth a full chapter, and in a sense it is — the value of a preset isn't conceptual complexity, it's the elimination of repeated manual work as the actual source of delivery errors.

Touring the Built-In Presets

Resolve ships with a substantial library of presets already built for common, named destinations — YouTube, Vimeo, various broadcast specifications, and other frequently used targets. These exist because the underlying technical requirements for those destinations are genuinely well known and don't vary project to project, which makes them a legitimate first stop rather than a shortcut to be suspicious of. Using a built-in preset correctly still requires knowing, from Chapter 11.2, roughly what it should contain — the preset saves the labor of setting each value, not the responsibility of knowing whether the result is actually appropriate for where the file is going.

A preset removes the labor of setting each value by hand. It doesn't remove the responsibility of knowing what those values should be — that judgment is still Chapter 11.2's, applied once and then reused.

Building and Saving a Custom Preset

Built-in presets don't cover every real situation — a specific client's delivery spec, a studio's own internal mezzanine standard, a recurring destination Resolve's defaults simply don't anticipate. In these cases, configuring a render job manually once, verifying it's genuinely correct against Chapter 11.2's considerations, and saving that configuration as a new named preset turns a one-time careful setup into a permanently reusable asset. This is worth doing the moment a non-standard delivery spec is going to recur even twice, rather than reconstructing the same settings from memory each time and risking a small, easy drift between renders that are supposed to be identical.

Presets as a Consistency Tool, Not Just a Speed Tool

It's worth naming the deeper value here plainly: a preset's real payoff isn't only the time saved on any single render, it's the guarantee that every render using it is configured identically. On a project with multiple deliverables, or a studio producing the same kind of output repeatedly across many projects, that consistency is what actually prevents the kind of quiet, one-off misconfiguration that a manual process eventually produces given enough repetitions. Part XII returns to this exact idea from the collaboration side — shared presets are one of the simplest, most concrete ways a team keeps delivery consistent across multiple editors, not just across one editor's own repeated work.

The One Common Mistake Worth Naming

The most frequent real error with presets isn't building one wrong — it's using the wrong one by default. Reaching for whatever preset was used last, or whichever sits first in a menu, without actively checking it against the actual destination's current requirements, is a habit worth catching early. A preset removes repeated manual labor; it was never meant to remove the moment of actually confirming that this render, going to this destination, calls for this preset specifically.

With presets covering the common, repeatable case, Chapter 11.4 turns to situations a full-timeline preset doesn't fit at all — rendering a single clip in place, or delivering just a portion of a timeline, rather than the whole thing at once.

Key Concepts to Remember

  • A render preset bundles Chapter 11.2's full set of technical decisions into one reusable, named choice.
  • Built-in presets cover well-known destinations reliably, but still require knowing whether their contents genuinely fit the job.
  • A custom preset is worth building the moment a non-standard delivery spec will recur — set up once carefully, reused safely after.
  • The most common preset mistake is using the wrong one by default — always confirm a preset against the render's actual destination.
