Chapter Two, Section Eight

Backing Up and Archiving a Project

Part II of XVI
Category Practical
Sheet 014 / 095
Depends On 2.1
Read Time ~8 Min

Chapter 2.1 raised a question and deliberately left it for later: if a project lives inside a database rather than as a single portable file, what does backing it up actually look like? This closing chapter of Part II answers that in full — three distinct tools, each solving a different part of the problem, and each worth understanding on its own rather than assuming any one of them covers everything.

Automatic Project Backups: The Safety Net You Barely Notice

Resolve includes an automatic project backup feature, running quietly in the background at an interval you can configure, saving periodic snapshots of your project's state without any manual action required. This isn't a substitute for the other tools in this chapter — it protects against a narrower, more common problem: an unexpected crash, a bad edit you want to roll back from, or simply wanting a recent known-good state to return to after an experimental session went nowhere useful. Confirming this feature is actually enabled, and that its backup interval and destination make sense for how you work, is a two-minute task worth doing on every new project rather than assuming a sensible default is already handling it.

The .drp File: A Portable Snapshot of the Database Record

When you genuinely need a standalone, portable file representing your project — to move it to a machine without shared database access, to send it to a collaborator, or to keep an external archival copy outside Resolve's own database entirely — you export one deliberately as a `.drp` file. This is the closest thing to the "single project file" model Chapter 2.1 explained Resolve doesn't use by default, and it exists specifically to bridge that gap when you need it.

A .drp file is a snapshot, not a live link. Once exported, it stops reflecting further changes to the project inside the database — treat it as a deliberate checkpoint, not a substitute for a project's ongoing life inside Resolve.

It's worth being clear about what a .drp file does and doesn't include. It captures the project's structure — Media Pool organization, timelines, grades, settings — but like the project itself, it references media rather than embedding it. Opening a .drp file on another system still requires that system to have access to the same source media, at a path Resolve can resolve or relink, exactly as Chapter 2.3 described. For genuinely self-contained portability, including the media itself, you need the third tool in this chapter.

Archiving: Project, Media, and Everything Between, Bundled Together

Resolve's archiving tools go a step further than a .drp export, bundling the project structure together with the actual media it references — camera originals, proxies, render cache, and grades — into a single, self-contained package intended for long-term storage or complete handoff. This is the right tool when a project is finished, or paused indefinitely, and you want a single, complete artifact that doesn't depend on the original folder structure, external drives, or even Resolve's own database still existing on the system that eventually needs to open it again.

Archiving is a heavier, more deliberate operation than the automatic backups or a quick .drp export — it's doing real work consolidating potentially large amounts of media — and it's not something you'd reasonably run daily. Treat it as the tool for genuine milestones: a finished delivery, a project going on long-term hold, or a client requesting a complete, self-contained copy of their work.

Matching the Tool to the Moment

Put together, these three tools cover three genuinely different situations, and knowing which one applies when is more useful than trying to remember all of them as an undifferentiated pile of "backup stuff." Automatic project backups protect your everyday working session against crashes and bad decisions, with no effort required from you beyond confirming they're on. A .drp export is for deliberately moving or sharing the project's structure on your own schedule, understanding it still depends on the media being reachable. A full archive is for the rare, weighty moment when a project needs to become one complete, self-contained thing — done, portable, and independent of anything else on the system that made it.

Key Concepts to Remember

  • Automatic project backups protect everyday work against crashes and mistakes — confirm they're enabled on every new project rather than assuming it.
  • A .drp export is a portable snapshot of project structure, but still references external media — it isn't self-contained on its own.
  • Full archiving bundles project and media together into one self-contained package — the right tool for finished work or long-term storage, not daily use.
  • Match the tool to the moment — routine safety, deliberate sharing, and final self-contained handoff are three different problems, not one.
